# エリア候補（上京住まい選びアプリの土台コレクション）

「上京住まい選びアプリ」の設計方針3原則のうち、特に「条件入力からの逆算」「体感情報」「見落としがちな注意」を1レコードに集約する台帳。

## レコード形状

- `id` — 主キー。半角英数・ハイフンのkebab-caseスラッグ（例: `nakano`）。ファイル名になる。
- `wardName` — 区名
- `stationName` — 最寄り駅名
- `lines` — 使える路線（複数、読点「、」区切りの自由記述。例: `JR山手線、東急東横線`）
- `commuteMinutes` — 勤務先までの所要時間（分）
- `transfers` — 乗り換え回数（終電の乗換回数としても兼用）

### 家賃グループ（出典付き）

- `rentRoomOnly` — 1R家賃（万円、幅可。自由記述。例: `7.96万円` `6.4〜6.6万円`）。**最新値のミラー**。
- `rentWithKitchen` — 1K家賃（万円、幅可。自由記述）。**最新値のミラー**。
- `rentSource` — 家賃の出典（例: `SUUMO・いえらぶ`）。**最新値のミラー**。
- `rentSurveyDate` — 家賃の調査時点（自由記述。例: `2026年7月`）。**最新値のミラー**。
- `rentStatus` — 家賃が確定値か推定値か（`✅ 確定` / `⚠️ 推定`）。**最新値のミラー**。
- `rentHistory` — **`table` 型。家賃の調査履歴（追記専用、上書き禁止）**。行は `{ date, roomOnly, withKitchen, source }`。調査するたびに新しい行を末尾に追加していく（既存行は消さない）。`rentRoomOnly` 等の「最新値のミラー」フィールドは、この履歴の最後の行と同じ内容を常に反映する運用。件数上限はなし（全履歴を保持）。比較ダッシュボードの詳細欄では、この配列の末尾4件（最新+過去3件）を新しい順で表示している。

### 終電グループ（出典付き）

想定ユーザー像より、勤務先（新宿）からの終電が重要な判断材料のため専用フィールドを用意。

- `lastTrainDepartTime` — 終電：新宿発時刻（自由記述）
- `lastTrainArriveTime` — 終電：最寄り駅着時刻（自由記述）
- `lastTrainFareYen` — 終電の運賃（円）
- `firstTrainTime` — 始発時刻（自由記述）
- `commuteSource` — 終電情報の出典（例: `駅探`）
- `commuteSurveyDate` — 終電情報の調査時点
- `commuteStatus` — 終電情報が確定値か推定値か（`✅ 確定` / `⚠️ 推定`）

### タクシー代グループ（出典付き）

- `taxiFareEstimate` — 終電後のタクシー代目安（円、幅可。自由記述。例: `2,500〜3,000円`）
- `taxiFareSource` — タクシー代の出典・根拠（例: `距離からの推定`）
- `taxiFareSurveyDate` — タクシー代の調査時点
- `taxiFareStatus` — タクシー代が確定値か推定値か（`✅ 確定` / `⚠️ 推定`）。距離からの概算はほぼ常に `⚠️ 推定`。

### 治安グループ（区と駅周辺を必ず両方持つ）

区全体の治安と、駅周辺（多くの場合、区内では悪い方に出る）の治安は評価が逆転するのが普通なので、常に両方を別フィールドとして持つ。**個別の犯罪事件（単発の事件報道）は記録しない** — 将来リスクの説明にならず、報道量の偏りを拾ってしまい、特定エリアへの風評被害にもなるため。記録するのは「傾向」「水準」といった集計的な評価のみ。

- `wardSafetyLevel` — 区の治安水準（23区内での相対位置。`上位（治安良好）` / `中位` / `下位（要注意）`）
- `stationSafetyLevel` — 駅周辺の治安評価（区内での相対位置。同じ3値）
- `crimeTendency` — 犯罪の主な傾向（自由記述。例: `自転車盗・万引きが中心。北口繁華街では深夜の酔客トラブルも一定数`）
- `violentCrimeLevel` — 凶悪犯罪の発生水準（`低い` / `平均的` / `高い`）
- `nightAtmosphere` — 夜間の雰囲気（街灯・人通り・駅前の客層。自由記述）
- `safetySource` / `safetySurveyDate` — 治安情報の出典・調査時点（グループ共通）

### 浸水グループ

「対象/対象外」の二択ではなく、区内の河川・駅周辺のリスク評価・過去の実績を別々に持つ。ハザードマップの「想定」に対して浸水履歴は「実績」であり、想定区域外でも実際に浸水した場所を拾える点が重要。

- `wardRivers` — 区内の中小河川名（複数、読点区切り。例: `神田川、妙正寺川`）
- `stationFloodRisk` — 駅周辺の浸水リスク（`要現地確認` / `低い` / `高い`）
- `floodHistory` — 過去の浸水履歴（自治体が公開している町丁目別の実績。自由記述）
- `floodCheckReminder` — 最終判定の確認方法メモ。判定は物件の住所が決まってから「東京都 浸水リスク検索サービス」で個別に確認する旨を記録する（全レコード共通のボイラープレート文でよい）
- `floodSource` / `floodSurveyDate` — 浸水情報の出典・調査時点（グループ共通）

### その他

- `shelterWalkMinutes` — 最寄り避難所までの徒歩分数
- `supermarket24hCount` — 24時間営業スーパーの数
- `weekdayClinicCount` — 平日診療している内科・歯科の数
- `goodReputation` — 街の良い評判（自由記述）
- `complaints` — 街の不満点（自由記述）

### 時間帯別の街の様子

設計方針3原則の「2. 体感情報」に対応。朝・昼・夜・深夜の4つの時間帯それぞれについて、メモと写真を1枚ずつ持てる。

- `morningNote` / `morningPhoto` — 朝の様子（メモ／写真）
- `noonNote` / `noonPhoto` — 昼の様子（メモ／写真）
- `nightNote` / `nightPhoto` — 夜の様子（メモ／写真）
- `midnightNote` / `midnightPhoto` — 深夜の様子（メモ／写真）

`〜Photo` は `image` 型フィールド（**ワークスペース相対パスの文字列を書き込む** — 添付画像なら `[Attached file: ...]` マーカーのパスをそのまま使う。`/api/files/raw?...` のようなURLは書き込まない）。1時間帯につき1枚のみ。複数枚持たせたい場合はフィールドの型を再検討すること（現状は「代表カット1枚」の設計）。

- `notes` — 総合メモ

すべて host-computed なフィールドは無し（全項目が書き込み可能）。

### 出典・確定/推定の運用ルール

新しい統計値（家賃・終電・タクシー代以外）を追加する場合も、同じ「値 / 出典 / 調査時点 / 確定・推定」の3点セットのパターンを踏襲してフィールドを増やす。`〜Status` enumの値は `✅ 確定` / `⚠️ 推定` に統一し、一覧表示・カード表示で推定値がひと目でわかるようにする（絵文字により追加CSSなしで視覚的に区別）。距離ベースの概算・未検証の値は必ず `⚠️ 推定` にする。

## 何をするか

**追加/更新** — `manageCollection` putItems。新規追加時は `mode: "create"`（id衝突を検出するため）、既存レコードの一部項目だけ更新するときは `mode: "merge"` で `{ id, <変更したい項目> }` を渡す（デフォルトの upsert はレコード全体を置き換えるので、省いた項目が消えてしまう点に注意）。
**一覧/参照** — `manageCollection` getItems。
**削除** — レコードを削除する場合は `manageCollection` deleteItems。
**スキーマ変更** — フィールドの追加/変更が必要なら `manageCollection` の `schemaDocs` → `getSchema` → `putSchema` の順で行う。`schema.json` を直接 Read/Write/Edit しない。

追加・更新のあとは `presentCollection`（slugとレコードidを指定）で inline 表示する。一覧表示のリクエストには slug のみ指定して呼ぶ。

## 自動更新: 家賃相場の週次リフレッシュ

`ingest.kind: "agent"`（`schedule: "daily"`, `atHour: 0` = 9:00 JST, `role: "general"`, `template: "templates/refresh-rent.md"`）。

- ホストのスケジューラは「毎日」の粒度でしか指定できないため、**実際には毎日9時(JST)にワーカーが起動する**。ただしテンプレート内の経過日数ガードにより、`area-candidates` の**全レコード**のうち**最終調査日がもっとも古いものが、現在から7日以上経過していなければ即終了**する（曜日では判定しない）。これにより「毎週1回程度」の頻度を保ちつつ、実行タイミングがずれても取りこぼさない（例: 月曜にPCが落ちていても、次に起動した日に実行される）。
- 最終調査日は `rentHistory` の最後の行の `date`（無ければ `rentSurveyDate`）から判定し、日付が読み取れない場合は安全側（＝実行する）に倒す。
- **対象は固定リストではなく、`area-candidates` コレクションの全レコード**（`getItems` を `ids` 指定なしで呼び、毎回そのときの全件を対象にする）。1R・1Kの家賃相場を駅ごとにWeb検索で調べ直す。新しいエリア候補を追加すると、次回の実行から自動的に更新対象に含まれる（調査履歴がまだ無いレコードは「7日以上経過」扱いになるので、次の実行を自動的にトリガーする）。テンプレートの修正なしにエリアを増減できる。
- **上書きではなく `rentHistory` に追記する。** 毎回の調査結果は `rentHistory` テーブルの末尾に新しい行として追加し、既存の履歴行は削除・変更しない。`rentRoomOnly` / `rentWithKitchen` / `rentSource` / `rentSurveyDate` / `rentStatus`（最新値のミラー）は今回の値で更新する。
- 変化の記録は2つの基準を独立に判定し、該当したものをすべて `notes`（総合メモ）に追記する（既存メモは保持し、末尾に追記）。**どちらの基準も、数値比較の前に必ず「比較可否チェック」を通す。**
  - **比較可否チェック**: (1) 比較相手の行の出典と今回の出典が完全一致しているか、(2) 比較相手の値・今回の値がどちらもレンジ表記でないか。どちらか一方でも条件を満たさなければ、その基準の数値比較（該当する1R/1K項目）はスキップし、理由を記録する。例: `【基準変更】出典がSUUMO→ニフティ不動産に変わったため、直前値との比較は行いません` / `【基準変更】前回値がレンジのため比較不可`（基準2＝初回値との比較の場合は「直前値」「前回値」を「初回値」に置き換える）。
  1. **直前比 ±5%** — 比較可否チェックを通過した場合のみ、`rentHistory` の最後の行（直前の調査値）と比較。例: `【家賃相場変動 2026-08-10】1R 7.96万円→8.5万円（+6.8%）。出典: SUUMO`
  2. **初回調査比 ±10%（累積変動）** — 比較可否チェックを通過した場合のみ、`rentHistory` の最初の行（初回調査時点の値）と比較。「【家賃相場 累積変動】」ラベルと「初回調査比」「調査期間 開始日〜終了日」を明記する。例: `【家賃相場 累積変動】1R 7.96万円→8.8万円（初回調査比+10.6%、調査期間 2026-08-01〜2026-10-05）`
  該当する事象（比較不可の通知／±5%変動／±10%累積変動）が複数あればすべて追記、何もなければ追記なし。
- `lastTrainDepartTime` 系（終電・始発）と `taxiFareEstimate` 系（タクシー代）、および治安・浸水・体感情報などは**このワーカーが変更してはいけないフィールド**として `templates/refresh-rent.md` に明記している。
- 手動で今すぐ試したい場合は、コレクションの「Refresh」ボタンから起動できる。ただし直近の更新から7日未満だと経過日数ガードにより何もせず終了する（すぐ試したい場合は対象レコードの `rentSurveyDate` / `rentHistory` の最終日付を7日以上前の日付に書き換えてから実行するか、テンプレートのガードを一時的に外すこと）。
- 失敗時はベル通知（「Collection refresh failed: area-candidates」）が出る。

## カスタムビュー: 比較ダッシュボード

`views/compare-dashboard.html`（`views[]` の id: `compare-dashboard`, capabilities: `["read"]`）。

- 各エリア候補をカードで並べ、区名・駅名・勤務先までの所要時間・家賃を上部に表示。
- 詳細欄の先頭に「家賃履歴（最新+過去の推移）」を表示。`rentHistory` テーブルの末尾4件（＝最新1件+過去3件）を新しい順のリストで表示し、最新の行は太字＋「最新」タグで強調する。
- **治安：区 vs 駅周辺の比較チップ**を常時表示（カードを開かなくても見える）。`wardSafetyLevel` と `stationSafetyLevel` を並べたチップで、それぞれ良好=緑／中位=グレー／要注意=赤に色分け。**両者の値が食い違う（逆転する）場合は警告色の枠と「⚠ 区と駅周辺で評価が異なる」タグで強調表示**する。
- 浸水リスク（`stationFloodRisk`: 低い=緑 / 要現地確認=グレー / 高い=赤）はバッジで色分け表示。
- カード詳細欄に「治安：犯罪の主な傾向」「凶悪犯罪の発生水準」「夜間の雰囲気」「浸水：区内の中小河川」「浸水：過去の浸水履歴」「浸水：最終判定の確認方法」を表示（出典・調査時点も併記）。
- 「深夜帰宅の可否」を `lastTrainDepartTime`（終電が0時台〜4時台か）と `taxiFareEstimate`（タクシー代目安の上限が5000円以内か）から自動判定してバッジ表示する。判定不能な場合は「情報不足」のニュートラルバッジになる。
- カードをクリックすると詳細（街の良い評判・不満点・24時間営業スーパーの数・平日診療の内科/歯科の数・時間帯別〔朝/昼/夜/深夜〕のメモと写真・総合メモ）が開閉する。写真は詳細を開いたタイミングで `GET <dataUrl>/image` 経由（3並列・429時1リトライ）で遅延解決し、解決済みの画像はパス単位でキャッシュして再オープン時に再取得しない。
- デザインはフラット（白背景・細い罫線・影/グラデーションなし）。色は状態を伝える情報（バッジの左端の縦線とドット）にのみ使い、文字は常に濃いグレー/黒で表示することでコントラストを確保している。
- `lastTrainDepartTime` / `taxiFareEstimate` は自由記述のため、判定ロジックが正しく機能するには時刻は `HH:MM` を含む形式、金額は半角数字（カンマ可）を含む形式で入力する必要がある。
